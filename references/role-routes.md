# 目标公司 AI 应用／Agent 岗位题路

本文件是教练内部选题索引。默认每轮只输出一个问题；按回答缺口选择一个追问，不一次展示题树、参考答案或评分点。`触发追问` 内的多个分支是候选路径，不是同轮问题清单。

## 路由与证据使用

本包没有预置候选人项目事实。下方具体项目、角色、框架、恢复路径、指标和使用阶段均为可选问题范例；仅在 STATE_DIR 中已有事实支持时用过去经历问法，否则先确认或明确转成假设。各条锚点描述不能作为新用户的履历声明。

- AI 模型工程师-Agent 技术、AI Agent 研发及高度相近岗位：优先研发版简历，先 Coding Agent 的架构、约束与验收，再落到 RAG、实习贡献和岗位适配。
- AI 应用开发及高度相近岗位：优先应用版简历，先 Run 服务和工程失败场景，再落到 RAG 全链路、实习收益与部署边界。
- 事实锚点指向 STATE_DIR/candidate-profile.md 的 F 编号（字段见 [candidate-profile.md](candidate-profile.md)），并结合 STATE_DIR 中的 `calibration.md` 最新适用的用户确认事实及来源。下面的“未确认／仅了解”描述对应初始材料，不冻结后续事实：用户确认新增实现后按真实实现追问，仍标明自述或材料核验等级；未确认时先问实际做法，候选人未做过时转成假设设计题。存在未解决冲突时先用一个问题核实，不自动覆盖任一来源。
- 一次回答出现多个缺口时，优先追问与岗位相关、影响事实可信度最大的一个；具体故障、诊断证据、替代方案、指标口径和个人贡献优先于名词罗列。
- 面经是有限的定性题路证据，不证明任何题必考，不构成正式统计频率，不是候选人履历，也不能直接成为反馈校准规则。

题路覆盖项目实现、困难定位、方案取舍、个人贡献、工程落地、Agent 协议与评测。它是可调整的训练索引，不表示某家公司的必考清单。用户提供的新岗位描述和真实反馈按反馈治理程序用于校准。

## AI Agent 技术路线

### G01 多角色条件状态机

- 主题：LangGraph 编排、角色职责与终止条件。
- 起始问题：请用一次实际修复任务说明 Orchestrator、Coding 和 Reviewer 之间怎样流转。
- 触发追问：只讲角色名 → “哪条状态信息决定下一条边？”；缺少理由 → “为什么用条件状态机组织这条修复链？”；失败／替代方案 → “如果 Reviewer 持续要求返修，你怎样结束任务？”或“换成单 Agent，最先失去哪项约束？”；未交代贡献 → 追问本人写的节点或条件边。
- 事实锚点：F16、F17；准确节点字段、阈值和并发方式未确认。

### G02 ReAct 与结构化动作

- 主题：推理到工具执行的动作合同。
- 起始问题：Coding 角色的一轮输出怎样变成系统可执行的动作？
- 触发追问：只有框架名称 → 选 Tool／Patch／Fact／Finish 中一种要求给实际输入输出；为什么 → “为什么需要 Pydantic 约束动作？”；失败／替代方案 → “模型输出合法 JSON 但语义越权时，哪一层阻止执行？”或“若改用自由文本解析，你预期出现什么故障？”
- 事实锚点：F17、F19；结构校验不自动证明语义安全，具体 schema 待确认。

### G03 上下文分层

- 主题：工作轨迹、稳定事实与持久化执行状态。
- 起始问题：在一个跨文件修复任务里，你把哪些信息放进工作轨迹，哪些记为稳定事实？
- 触发追问：只列名称 → 请求一个真实信息跨层例子；为什么 → “为什么不把全部历史原样放进上下文？”；失败／替代方案 → “需求变更使旧事实失效时，你如何避免继续沿用？”或“压缩摘要遗漏关键证据时如何恢复？”
- 事实锚点：F18；摘要算法、淘汰策略和 token 收益未载明，未做过则转设计题。

### G04 Checkpoint 与四类恢复

- 主题：继续、中断恢复、需求修订、干净重启。
- 起始问题：请举一个需要中断恢复而不是干净重启的实际场景。
- 触发追问：把恢复等同重跑 → 追问恢复所需最小状态；为什么 → “为什么需求修订不能直接复用全部旧状态？”；失败／替代方案 → “若文件已被外部修改，Checkpoint 中的候选还能否继续？”或“没有 Checkpoint 时重放日志有何代价？”
- 事实锚点：F18、F19、F23；只确认设计过四条恢复路径，不预设故障演练覆盖。

### G05 安全权限与 Patch 写回

- 主题：默认拒绝、授权范围、候选隔离与分层校验。
- 起始问题：一个 Patch 从模型产出到写回原工作区，要经过哪些实际检查？
- 触发追问：只提 Docker → 追问权限和沙盒的责任边界；为什么 → “为什么验证通过后还要检查文件哈希？”；失败／替代方案 → “测试通过但修改触及未授权文件时怎么处置？”或“只用 AST 检查替代沙盒验证，会漏掉什么？”
- 事实锚点：F19；不把容器等同绝对隔离，不预设网络或资源限制已经实现。

### G06 独立验收

- 主题：冻结验收合同、TestBuilder 隔离与 Reviewer 证据。
- 起始问题：你如何防止 Coding 角色通过修改验收标准让自己的修复过关？
- 触发追问：只说独立 Reviewer → 要求解释实际信息或权限边界；为什么 → “为什么合同要在修复前冻结？”；失败／替代方案 → “新增测试全通过但官方回归失败，如何定位验收缺口？”或“只依靠同一个模型自评会出现什么偏差？”
- 事实锚点：F20；独立角色不自动意味着无数据泄漏，具体隔离实现待回答。

### G07 MCP

- 主题：协议理解、Host／Client／Server 与工具调用路径。
- 起始问题：你简历中写了解 MCP，请从一次模型选择工具开始解释完整调用路径。
- 触发追问：混淆主体 → 只追一个主体职责；为什么 → “为什么需要 MCP 协议层，直接接函数有什么差异？”；失败／替代方案 → “假设可发现的工具太多，你会怎样降低上下文成本？”或“工具超时或返回不可信内容时，谁负责处理？”；自称已实现 → 先请用户明确补充项目证据，不自动录入。
- 事实锚点：F02及后续已确认的 MCP 补充事实。初始材料仅记载了解协议；未确认实现时，工程接入使用“假设要接入”。新增实现经用户明确确认并记录来源后，转为实际接入经历追问，核验等级保持原样；不以旧简历未列出为由拒绝补充。

### G08 Memory

- 主题：任务记忆、相关性、失效与持久状态区别。
- 起始问题：你项目里的稳定事实与 Checkpoint 状态，在用途上有什么区别？
- 触发追问：只讲长期记忆术语 → 请求项目内一个真实记忆条目；为什么 → “为什么不是所有历史动作都进入稳定事实？”；失败／替代方案 → “错误事实进入记忆后，如何发现并撤回？”或“若仅用长上下文保留历史，会有哪些代价？”
- 事实锚点：F18、F02；跨会话／跨用户长期记忆未证实，未实现策略作为设计回答。

### G09 Agent vs Workflow

- 主题：确定性编排与模型自主决策边界。
- 起始问题：你的项目哪些步骤是固定 Workflow，哪些决策由 Agent 动态作出？
- 触发追问：把所有节点称为自主 Agent → 指定一条条件边说明决策来源；为什么 → “为什么这个环节需要模型决定？”；失败／替代方案 → “如果任务变得高度固定，如何改成更简单的 Workflow？”或“模型目标漂移时哪项确定性约束兜底？”
- 事实锚点：F17、F19、F20；不得假定“用了 LangGraph 就是完全自主 Agent”。

### G10 Multi-Agent 的收益与代价

- 主题：多角色是否必要、协调和证据共享。
- 起始问题：你的多角色拆分解决了单 Agent 链路中的哪一个具体问题？
- 触发追问：笼统说效果更好 → 要求真实例子或比较证据；为什么 → “为什么把 Reviewer 独立出来？”；失败／替代方案 → “多个角色意见冲突时最终由谁决定？”或“怎样设计单 Agent 对照判断额外成本是否值得？”
- 事实锚点：F17、F20；有多角色设计事实，没有统一优越性、消融数据或并行执行事实。

### G11 评测与失败分析

- 主题：Pass@1、单候选、F2P、验收泄漏与代表性。
- 起始问题：你的代码修复成功率，是按什么样本和候选选择规则得到的？
- 触发追问：只报百分比 → 追候选选择及内部返修关系；为什么 → “为什么用这个评测口径？”；失败／替代方案 → “请选一个真实失败 Issue，说明你已有的定位证据。”或“若要比较另一方案，如何保持评测条件一致？”；未记得失败细节 → 登记缺证据，不补造分类。
- 事实锚点：F20；小样本离线验证，不能外推生产可靠性；问题选择与泄漏控制未确认。

### G12 Skill 与 Harness 的治理

- 主题：业务知识、候选匹配、审核与沉淀。
- 起始问题：你独立交付的 Harness 与你参与建设的 Skill 治理分别解决什么问题？
- 触发追问：把两者混为报表 Skill → 要求列实际交付物；为什么 → “为什么语义等价确认不能直接决定知识沉淀？”；失败／替代方案 → “高频候选与已有规则冲突时怎么办？”或“把审核和沉淀合并成一步，会失去什么核验？”
- 事实锚点：F04、F08-F11；团队方案与个人实现分开，自动闭环规划不能说成已上线。

## AI 应用开发路线

以下每题至少有一个工程落地分支；若该分支不在来源中，先核对实际实现，未做过则明确问假设设计。

### A01 Run 服务化

- 主题：长任务资源模型与 API 生命周期。
- 起始问题：为什么把一次代码修复封装成 Run 资源？
- 触发追问：工程落地 → “客户端提交后立即断开，怎样再次找到这次任务？”；只列 API → 要求一个真实请求到 run_id 的路径；替代方案 → 追同步 HTTP 执行的限制。
- 事实锚点：F21；具体接口 URL、鉴权和部署形态未确认。

### A02 幂等创建

- 主题：重复提交、请求身份与冲突语义。
- 起始问题：你实现的幂等创建怎样判定两个请求是同一个 Run？
- 触发追问：工程落地 → “两个相同请求同时到达时，哪一层保证只创建一个 Run？”；只说缓存 → 追问崩溃后结果；未实现并发冲突 → 改问假设如何设计；不预设唯一约束或幂等键已有实现。
- 事实锚点：F21、F23；创建幂等与工具副作用幂等是不同边界。

### A03 状态查询

- 主题：Run 状态与执行节点的对外语义。
- 起始问题：客户端查询 Run 状态时，怎样区分运行中、人工等待和已经结束？
- 触发追问：工程落地 → “Worker 已停止但数据库仍显示运行中，你的现有系统如何发现？”；未经验证 → 转故障处理设计；将图节点当服务状态 → 追两者映射。
- 事实锚点：F22、F23；不预设完整枚举、心跳、租约、监控或故障接管已实现。

### A04 SSE 与进度续传

- 主题：事件订阅、断连重连与客户端消费。
- 起始问题：客户端 SSE 连接断开后，你怎样让它继续看到任务进度？
- 触发追问：工程落地 → “客户端重连时收到重复事件，怎样避免界面重复展示？”；只说重连 → 追问事件序号从哪里取；替代方案 → “为什么选 SSE 而不是轮询或 WebSocket？”；具体保留期限和续传 header 未证实则按设计题处理。
- 事实锚点：F21、F23。

### A05 队列与 Worker

- 主题：异步执行、重复投递与进程故障。
- 起始问题：一个 Run 从提交到 Worker 执行 LangGraph，经过哪些组件？
- 触发追问：工程落地 → “任务已出队但 Worker 在写状态前崩溃，你当前如何处理？”；只列产品名 → 追实际责任边界；重试方案 → 追重复执行对副作用的影响。
- 事实锚点：F22、F23；队列产品、投递语义和分布式协调方案未记载。

### A06 协作式取消与人工恢复

- 主题：取消检查点、不可中断动作和半完成状态。
- 起始问题：运行中的取消请求怎样传到正在执行的任务？
- 触发追问：工程落地 → “取消到达时 Docker 验证正在执行，系统下一步实际怎么做？”；混淆人工等待与取消 → 追两者状态区别；为什么 → “为什么不用直接终止进程？”；没有现成行为 → 显式转设计。
- 事实锚点：F22、F19；不能预设即时取消、回滚所有副作用或每种状态都可恢复。

### A07 PostgreSQL 状态与追加式事件

- 主题：可查询业务状态、事件顺序与一致性。
- 起始问题：Run 状态和追加式事件分别解决什么问题？
- 触发追问：工程落地 → “状态更新成功而事件写入失败时，你的系统会呈现什么？”；若使用事务 → 再追覆盖边界；只说持久化可靠 → 追事件序号竞争；未实现一致性机制 → 转设计取舍。
- 事实锚点：F23；未确认事务、Outbox、全局或单 Run 序号规则，不替候选人作答。

### A08 Checkpoint 与服务恢复

- 主题：业务状态与 LangGraph 执行上下文对齐。
- 起始问题：PostgreSQL 中已有 Run 状态，为什么还需要 LangGraph Checkpoint？
- 触发追问：工程落地 → “Run 状态比 Checkpoint 更新得更晚时，重启后从哪里恢复？”；把事件续传等同执行恢复 → 要求区分客户端与 Worker；若应用版未讲四类恢复 → 可从研发版 F18 进一步询问，注明出处。
- 事实锚点：F18、F23；不保证多存储原子一致，不预设 Checkpoint 具体后端。

### A09 工具重试与幂等

- 主题：副作用、重试身份与重复写回。
- 起始问题：你为哪一种工具动作实现过幂等约束？
- 触发追问：工程落地 → “动作已经成功，但确认响应丢失后被重试，怎样识别已完成？”；只有概念 → 要求动作级实例；无法提供 → 记为待补证据并转设计；替代方案 → 追幂等与补偿各适用什么动作。
- 事实锚点：F23、F19；不把 Run 创建幂等当作全部副作用恰好一次。

### A10 RAG 全链路

- 主题：解析、切分、召回、融合、重排到回答。
- 起始问题：请从一份跨页表格 PDF 到一次查询回答，说明你的 RAG 链路。
- 触发追问：工程落地 → “用户答错的问题来自解析、召回还是生成，你怎样分层定位？”；不清贡献 → 追本人负责模块；替代方案 → 追为何结合 BM25 和向量检索；生成端未记载 → 先确认模型、引用与拒答机制是否实际实现。
- 事实锚点：F12-F15；离线解析模块负责人，不默认独立开发全链路。

### A11 RAG 指标与检索取舍

- 主题：不同解析、切分和系统评测的指标及证据范围。
- 起始问题：请选一项检索优化说明评测结果究竟证明了什么。
- 触发追问：工程落地 → “新文档分布变化时，你会怎样发现召回退化？”；评测 → 追标注、基线和测试隔离；取舍 → 追重排对延迟与质量的影响，未提供的数据保持未知。
- 事实锚点：F13-F15；各指标及数据集分开，不混为回答准确率。

### A12 数据链路与业务收益

- 主题：真实业务瓶颈、映射、采集完整性与收益口径。
- 起始问题：数据链路带来的效率改善，具体缩短的是哪一段？
- 触发追问：工程落地 → “某店铺当天没有打开目标页面，报表怎样识别缺数据？”；具体故障 → 追已入库却查询不到的定位链；只有数字 → 追同时间段人工核对方法；未做缺失告警 → 转设计，不假装已有。
- 事实锚点：F05-F07；内部使用、人工打开页面、实际采集耗时口径。

### A13 Harness 与应用交付

- 主题：业务口径、可调用接口及上层能力范围。
- 起始问题：你的 Harness 文档怎样让 Agent 正确使用业务查询接口？
- 触发追问：工程落地 → “业务新增一个指标时，哪些映射、文档和查询环节需要同步？”；只讲抽象知识 → 要求一个实际字段映射；过度声称已实现所有 Skill → 回到已交付物和计划；治理细节 → 进入 G12。
- 事实锚点：F08-F10；单品牌四板块，独立文档交付和参与治理分开。

### A14 生产边界与可交付性

- 主题：个人实现、内部使用、离线验证与生产上线的差距。
- 起始问题：请选一个项目说明它目前实际运行到了什么阶段。
- 触发追问：工程落地 → “如果把个人 Run 服务交给业务用户，你首先需要补齐哪项可靠性能力？”；将真实 Issue 评测当生产 → 追用户、环境与负载证据；只讲功能 → 追部署、认证、观测、运维中的一个实际缺口；未做过一律允许说明假设方案。
- 事实锚点：F05、F12、F16、F20-F23；仅数据链路确认内部使用，RAG 与 Coding Agent 的生产部署未确认。

## 两条路线共用的补充入口

### C01 个人贡献与困难

- 主题：设计、实现、验证各由谁负责。
- 起始问题：请选一个你亲自解决的最困难问题，先说你负责的部分。
- 触发追问：只讲团队 → 追本人代码或决策；只有结果 → 追定位证据；真实失败缺细节 → 允许标注不确定，不编日志；团队治理可用 F09，离线解析可用 F12。
- 事实锚点：F04、F07、F09、F12、F16。

### C02 主管面与岗位适配

- 主题：协作、冲突、期限、客户问题和动机。
- 起始问题：你希望在目标公司这个岗位解决哪类问题，哪段已有经历能说明匹配？
- 触发追问：抽象价值观 → 追一个真实协作或需求取舍事件；声称冲突解决 → 追对方诉求与本人行动；讨论期限 → 追实际优先级和风险沟通；无来源的团队故事必须由用户提供。
- 事实锚点：F04-F12、F16；题路不提供候选人动机或管理事实。

### C03 基础与算法补充

- 主题：与回答缺口相关的 Transformer、工具调用基础及算法表达。
- 起始问题：按本场岗位与已暴露缺口选择一道具体基础题或算法题，实际输出时只呈现选中的一道。
- 触发追问：基础解释不清 → 选与当前项目直接相关的一个机制；算法题 → 根据代码追正确性、边界或复杂度中的一个；算法题范围按岗位和候选人需求选择。
- 事实锚点：F02；知识考查不证明候选人已训练模型或做过 GPU 优化。
